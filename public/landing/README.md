The initial eight product screenshots were captured on 2026-11-08. Five desktop captures use the current Accessible Smart Map web application; three native captures use the iOS app in the iPhone 18 Pro simulator running iOS 27.0. The local frontend at `http://127.0.0.1:3102/map/` used the existing development proxy to the real backend on port 8000. No mock responses, generated imagery, substituted interface content, or fabricated routes were used. Desktop captures used an isolated anonymous browser session with light theme and public destinations. The native app used the existing installed development build with current project JavaScript served by local Metro and a temporary `EXPO_PUBLIC_END_POINT=http://127.0.0.1:8000` override. Native capture used public endpoints; no account identity, saved places or search-history lists appear in the published image, and no device location was used as a route endpoint.

## Media authenticity correction and iPhone frames — 2026-11-09

All native phone screenshots on the landing page use the shared Magic UI `Iphone` frame (`src/components/ui/iphone.tsx`), including both BusPreview tabs. The original screenshot content is fitted inside the frame without cropping; the device bezel and Dynamic Island belong to the mockup.

The previously referenced `assistant.mp4` and `navigation-live.mp4` are no longer used anywhere on the homepage. Inspection of extracted video frames against the source images found an added colored waveform over the idle chat screenshot and an added radar ring over the navigation screenshot. These are illustrative overlays, not recordings of the application's voice interaction or live route tracking. Earlier descriptions of those files as live demonstrations were incorrect. The files remain in the working tree as unused assets; they must not be reused as actual product footage.

The Hero and non-voice gallery cards display the original native screenshots. `assistant-native.webp` preserves the real `/chat` initial text-chat state and its voice-entry button, not an active voice session; it has been superseded in the gallery by the genuine voice capture documented below. The actual voice panel has separate status/transcript content plus mute/end controls and requires login. No voice-session state, audio waveform, user message, reply, or navigation movement is fabricated for the homepage.

Source comparison evidence is in `.local/landing-fix/assistant-existing-video-frame.png`, `.local/landing-fix/navigation-live-existing-video-frame.png`, and the original `/tmp/homepage-app-captures/assistant-native.png`. The older `output/homepage-redesign/recapture/` path documented above is historical and was not present during this audit.

The App gallery reserves space for the measured captions, scales the phones to the available viewport height, and uses 12 px padding at both ends. Its vertical scroll moves the track from the first card's left edge to the last card's right edge, with no centered leading or trailing blank area. The feature overview continues to cover voice navigation, live bus arrivals/filtering/reminders, text/voice AI assistance, nearby accessibility facilities, parking, weather/air quality, mapped indoor venues, hazard reports and SOS.

## Genuine voice-session recording — 2026-11-09

After the user completed login, the normal on-screen voice button in `/chat` successfully connected to the voice service. The iPhone 18 Pro / iOS 27.0 simulator displayed `聆聽中…`, `請開始說話`, the application's own blue waveform, and its mute/end buttons. This is the application's real listening state; no spoken query or AI reply is demonstrated. The capture contains no account identity or conversation transcript. The session was ended through its normal button after recording.

`assistant-voice-native.mp4` is a 12-second excerpt (15–27 seconds) from the 37.485-second simulator recording, encoded as H.264 at 804 × 1748 / 30 fps. Only temporal trimming, proportional resizing, frame-rate conversion and compression were applied; there are no image overlays or fabricated animations. This is a screen-only recording with no audio track. `assistant-voice-native.webp` and its 360/720 px variants come from an unmodified screenshot of the same connected listening state. The gallery loops the recording silently and displays the screenshot instead when reduced motion is enabled.

Raw evidence is stored in `.local/landing-fix/voice-capture-20261109/assistant-voice-raw.mov` and `assistant-voice-native.png`, alongside extracted comparison frames. The installed development client used the current mobile checkout (`b346728`) served by Metro on port 8082. No mobile source code or application state was patched. CoreSimulator could not write the video directly to the external volume, so it initially wrote to `/tmp` and the original recording was then copied to KINGSTON.
